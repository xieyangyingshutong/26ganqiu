# STM32F103C8T6 球杆 PID 控制项目

## 1. 系统结构

本工程使用两路互相独立的串口：

- `USART1`：PA9(TX)、PA10(RX)，115200/8N1，连接 Emm_V5 闭环步进驱动器。
- `USART3`：PB10(TX)、PB11(RX)，115200/8N1，连接 K230 的 UART4。

K230 继续运行根目录下的 `demo-camera(3).py`。STM32 不修改其三种模式，直接使用脚本发出的球位置、球速度和目标位置。

控制结构为：

```text
K230视觉位置/速度 -> STM32球位置PID -> 目标梁角度
                  -> 曲柄绝对脉冲位置 -> Emm_V5内部电机位置环
```

## 2. 接线

### K230 与 STM32

| K230 | STM32F103C8T6 | 说明 |
|---|---|---|
| GPIO36 / UART4_TXD | PB11 / USART3_RX | 必接，交叉连接 |
| GPIO37 / UART4_RXD | PB10 / USART3_TX | 当前脚本不接收数据，可选 |
| GND | GND | 必须共地 |

两端必须使用 3.3 V TTL 电平，不要直接接 RS-232 电平。

### STM32 与 Emm_V5

| STM32F103C8T6 | Emm_V5 | 说明 |
|---|---|---|
| PA9 / USART1_TX | RX | 电机命令 |
| PA10 / USART1_RX | TX | 可接收电机回包；当前兼容控制不依赖该回包 |
| GND | GND | 必须共地 |

## 3. 上电前必须完成的机械检查

1. 右端转动支点必须能够自由转动，不能把水管刚性锁死。
2. 曲柄应停在局部单调工作区，任何允许的命令都不能让曲柄越过机械死点。
3. 人工把水管调到水平，再给 STM32 和电机驱动器上电。
4. 默认配置会调用 `Emm_V5_Reset_CurPos_To_Zero()`，把上电时的当前位置声明为绝对零点。该命令不移动电机，但如果上电时水管不水平，之后所有控制都会带有零点偏差。
5. 第一次试机应扶住或限制机构行程，并准备立即断开电机使能/电源。

当前机构没有限位开关或独立倾角传感器，因此软件硬限位不能替代机械限位。

## 4. K230 数据包

每帧 12 字节：

```text
AA 55 | seq | flags | confidence | position_i16 | velocity_i16 |
setpoint_i16 | xor
```

- 多字节数据为小端。
- 位置和目标单位为 0.1 mm。
- 速度单位为 0.1 mm/s。
- `flags.bit0`：球位置有效。
- `flags.bit1`：目标有效。
- `flags.bit2`：当前图像真实检测到滑轨。
- `flags.bit6`：当前图像真实检测到球。
- `flags.bit7`：K230 正在做端点丢球恢复。

STM32 只有在帧头、XOR、模式、置信度和位置范围均合法后才发布数据。

## 5. 安全状态机

- 上电保持水平，等待 K230。
- 收到一帧“球真实检测 + 目标有效 + 置信度不低于 20%”的数据后进入 PID；不再要求滑轨检测必须在同一帧 fresh，与实机可用的 `ZDT/1` 规则一致。
- 普通短时预测最多接受 220 ms。
- 端点恢复最多接受 350 ms。
- 250 ms 没有合法 K230 包，或球/目标失效，PID 复位并按设定斜率回到水平零点。
- 电机命令始终受梁角限幅、绝对脉冲硬限位和变化率限幅三重约束。
- 电机控制已改为与 `ZDT/1` 相同的 `Emm_V5_Pos_Control()`（功能码 `0xFD`）普通绝对位置命令，方向由正负目标转换，`raF=1` 防止曲柄连续旋转。
- 上电顺序与 `ZDT/1` 一致：使能、等待 20 ms、当前位置清零、等待 20 ms、发送水平绝对位置；不再因 PA10 无回包或驱动器不支持 `F1/FC` 而锁死控制。

可在 Keil Watch 中观察全局变量 `ball_control_status`。主要状态值：

| 值 | 状态 |
|---:|---|
| 0 | 等待 K230 |
| 1 | 收到首帧真实球数据，正在进入控制 |
| 2 | 正常 PID |
| 3 | 短时预测控制 |
| 4 | 端点恢复控制 |
| 5 | 球、滑轨或目标无效 |
| 6 | K230 通信超时 |
| 7 | 保留的内部电机故障状态；当前兼容模式不作回包判定 |

`ball_control_status.motor_link_ready` 上电初始化后应为 1；`motor_last_function` 应为 `0xFD`，`motor_commands_sent` 会随控制命令递增。`desired_motor_pulses` 表示 PID 目标，`sent_motor_pulses` 表示最近一次已发送的绝对位置。

### 电机固件要求

该控制环使用现有库中的 `Emm_V5_Pos_Control()`（`0xFD`），与 `ZDT/1` 已在同一机构上工作的实现一致，不要求驱动固件支持 `F1/FC`。驱动器地址必须为 1、波特率为 115200，命令校验采用库中固定的 `0x6B`。PA9→驱动器 RX 和共地是运动必需连接；PA10 回包不参与控制判定。仍建议关闭定时自动回传和本地回显，避免无用中断流量。

## 6. 首次必须标定的参数

全部集中在 `APP/ball_control_config.h`：

### `BALL_MOTOR_DIRECTION_SIGN`

默认 `+1.0f`。定义正方向为：PID 输出为正时，应使钢球向刻度正方向运动。

若钢球明显加速远离目标，立即停机，将该值改成 `-1.0f`。不要试图通过继续增大 PID 来修正方向错误。

### `BALL_MOTOR_PULSES_PER_BEAM_DEGREE`

这是曲柄机构的传动标定值，不能只由电机细分数推导。

测量方法：

1. 水平位置清零。
2. 发送一个很小的绝对脉冲位置，例如 20～40 脉冲。
3. 用倾角仪测量水管实际改变的角度。
4. 计算 `脉冲变化量 / 梁角变化量`。
5. 在正、负两个方向重复测量，并只使用近似线性的安全区。

默认值 40 pulse/beam-degree 只是保守起点。

### `BALL_MOTOR_LEVEL_PULSES`、`BALL_MOTOR_MIN_PULSES`、`BALL_MOTOR_MAX_PULSES`

`LEVEL` 是水管水平时驱动器的绝对脉冲坐标；启用“上电当前位置清零”时必须保持为 0。`MIN` 和 `MAX` 必须分别根据曲柄离两个机械死点的实际距离测量，允许不对称。当前采用 `ZDT/1` 已用参数 -320～+320 脉冲和最大 ±8° 软件输出，但仍必须根据你这套曲柄离机械死点的真实距离确认。若三者顺序错误，或自动清零时 `LEVEL` 不为 0，工程会在编译阶段报错。

## 7. PID 调节顺序

默认参数采用梁角度作为输出单位：

```text
Kp = 0.05000 deg/mm
Ki = 0.00375 deg/(mm*s)
Kd = 0.00875 deg/(mm/s)
最大梁角 = +/-8.0 deg
梁角变化率 = 30 deg/s
```

控制式为：

```text
error = filtered_setpoint - ball_position
angle = Kp*error + integral - Kd*ball_velocity
```

D 项直接使用 K230 已滤波的球速度，因此触摸目标或模式 2 切换目标时不会产生误差微分冲击。

配合默认 `40 pulse/beam-degree`，上述参数等效于 `ZDT/1` 的 `Kp=2.00`、`Ki=0.15`、`Kd=0.35` 脉冲输出参数。

推荐顺序：

1. 先确认零点、方向、传动比和机械极限。
2. 暂时令 `Ki=0`，并把最大梁角降到 0.5～1.0°验证负反馈。
3. 逐渐增大 Kp，直到响应足够快但尚未持续往返。
4. 增大 Kd 抑制过冲和摆动。
5. 最后小幅增加 Ki，只用于消除水平误差、装配偏差等静差。
6. 模式 1 稳定后再测试模式 2 和模式 3。

高频抖动通常应先检查视觉坐标抖动、曲柄间隙和 Kd；慢速大幅往返通常应减小 Kp 或增加 Kd。长期偏向一侧应先重新校平，而不是优先增大 Ki。

## 8. 工程文件

- `APP/ball_main.c`：当前参与编译的主程序。
- `APP/ball_control.c/.h`：状态机、PID、限幅和电机命令调度。
- `APP/ball_control_config.h`：所有需要现场标定的参数。
- `BSP/camera_uart.c/.h`：USART3 和 K230 固定帧解析。
- `DRIVERS/timebase.c/.h`：1 ms SysTick 时基。
- `CMSIS/startup_stm32f10x_md.s`：STM32F103C8 中容量器件中断向量和启动文件。

原 `APP/main.c` 保留为厂商电机示例，但已从 Keil 编译目标中替换掉。

注意：永久时基启动后不能再调用旧 `delay_ms()`，因为旧函数会重新配置并关闭 SysTick。当前程序只在 `timebase_init()` 之前使用它。
